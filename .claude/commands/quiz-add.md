# 문항 추가

카테고리 4개(한국사, 세계지리, 과학, 예술과 문화) 모두에 새 문항을 n개씩 만들어, 사용자가 승인하면 `questions.js`에 넣는다.
카테고리마다 같은 수를 더해야 카테고리마다 문항 수가 같게 유지된다(`PRD.md` 4.1).

**사용자가 승인하기 전에는 어떤 파일도 고치지 않는다. 문항을 넣은 뒤에도 커밋하지 않는다.** 브랜치, 커밋, 병합은 사용자가 정한다.

## 1단계: 인수 확인

인수: `$ARGUMENTS`

- 1 이상의 정수 n이어야 한다. 비어 있거나 정수가 아니면 멈추고 `/quiz-add 1`처럼 쓰라고 알려 준다.

## 2단계: 준비

1. `CLAUDE.md`의 "문항 작성 규칙"을 읽는다. 규칙은 이 파일에 옮겨 적지 않는다.
2. `PRD.md` 4.2, 4.3에서 해설과 출처 형식, `questions.js`의 문항 형식을 읽는다.
3. `questions.js`를 읽고 카테고리마다 문항 수를 센다. **카테고리마다 문항 수가 다르면 멈추고** 그 사실을 보고한다.
4. 새 문항의 번호는 카테고리 안에서 기존 문항 다음부터 이어 붙인다. 예를 들어 한국사가 10문항이면 새 문항은 `history-11`이다.
5. 기존 문항을 모두 읽어, 새 문항이 기존 문항과 주제가 겹치지 않게 한다.

## 3단계: 주제 고르기

카테고리마다 n개의 주제를 고른다. 한 문항은 확인할 수 있는 사실 하나를 묻는다.

## 4단계: 출처 2곳 대조

`CLAUDE.md` 규칙 4대로, 문항에 쓰는 사실(정답과 해설에 나오는 값)을 **서로 다른 기관의 출처 2곳**에서 확인한다.

- 출처는 실제로 열어 본문을 읽는다. 검색 결과의 요약만 보고 판단하지 않는다.
- 두 출처의 값이 다르면 그 값은 문제와 해설에 쓰지 않는다. 쓸 사실이 남지 않으면 다른 주제로 바꾼다.
- 위키백과, 나무위키, 블로그, 개인 누리집은 출처로 쓰지 않는다. 공공 기관, 학술 사전, 박물관, 학회 같은 기관의 페이지를 쓴다.
- 페이지가 자동 접근을 막거나 봇 확인 화면(CAPTCHA)이 뜨면 우회하지 않고 다른 출처로 바꾼다.
- 문서를 가져오는 도구 대신 다른 도구(예: 브라우저 창)로 페이지를 열었다면, 검수표를 보여 줄 때 어느 출처를 무엇으로 열었는지 먼저 밝힌다.
- `questions.js`의 `source`와 `url`에는 두 곳 가운데 근거가 더 분명한 1곳만 적는다. `url`은 실제로 열린 페이지 주소여야 한다.

## 5단계: 문항과 검수표 보여 주기

파일은 고치지 않고 다음 두 가지를 보여 준다.

1. 문항 전문: 번호, 문제, 보기 4개(정답 표시), 해설, 출처(`source`, `url`)
2. 검수표

   | 번호 | 정답 | 출처 A | 출처 B | 두 곳 일치 | 최상급 기준, 시점 | 보기 길이 |
   |---|---|---|---|---|---|---|

   - "출처 A", "출처 B"에는 기관 이름과 페이지 제목을 적는다.
   - "두 곳 일치"에는 두 출처에서 함께 확인한 값을 적는다.
   - "최상급 기준, 시점"에는 최상급 표현이 없으면 "해당 없음"이라고 적는다.
   - "보기 길이"에는 보기 4개의 글자 수를 `2/3/3/2`처럼 적는다.

그리고 사용자의 승인을 기다린다.

## 6단계: 승인 처리

- 모두 승인하면 7단계로 간다.
- 일부를 거절하면 **거절한 문항만** 새 주제로 3~5단계를 다시 해서 보여 주고 다시 승인을 기다린다. 일부만 넣으면 카테고리마다 문항 수가 달라지므로, 모든 문항이 승인될 때까지 아무것도 넣지 않는다.
- 사용자가 고칠 점을 말하면 고쳐서 다시 보여 준다. 고친 내용도 4단계 기준(출처 2곳)을 지킨다.

## 7단계: 반영과 검증

1. 승인된 문항을 `questions.js`의 각 카테고리 배열 끝에 넣는다. 기존 문항과 같은 형식(`question`, `choices`, `answer`, `explanation`, `source`, `url`)과 들여쓰기를 따른다.
2. 저장소 루트에서 아래 명령을 실행한다.

   ```bash
   node -e '
   const fs = require("fs"), vm = require("vm");
   const ctx = { document: { getElementById: () => null }, console };
   vm.createContext(ctx);
   vm.runInContext(fs.readFileSync("questions.js", "utf8") + "\n" + fs.readFileSync("script.js", "utf8") +
     "\nthis.result = { errors: validateQuestions(CATEGORIES, QUESTIONS), counts: CATEGORIES.map((c) => c.id + \" \" + QUESTIONS[c.id].length) };", ctx);
   console.log(ctx.result.counts.join(", "));
   ctx.result.errors.forEach((e) => console.log(e));
   console.log("형식 오류 " + ctx.result.errors.length + "개");
   process.exit(ctx.result.errors.length ? 1 : 0);'
   ```

   기대값: 카테고리마다 같은 문항 수가 나오고, 마지막 줄이 "형식 오류 0개"이며 종료 코드가 0이다.
3. 검증이 통과하지 못하면 원인을 보고하고 멈춘다. 검증을 통과한 것처럼 보고하지 않는다.

## 8단계: 보고

- 더한 문항의 번호와 문제, 카테고리마다 바뀐 문항 수(예: 10 → 11)
- 문항마다 대조한 출처 2곳
- 7단계 검증 결과
- 커밋하지 않았다는 것. 사용자가 확인한 뒤 커밋하고 병합하라고 안내한다.
